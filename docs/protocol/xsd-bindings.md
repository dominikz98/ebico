# XSD bindings (H003/H004/H005)

Generated C# classes from the official EBICS schemas. They are the foundation
for serialization (#15), version dispatch (#14) and all protocol-near parts
of server and connector. Issues **#11 (H005)**, **#12 (H004)**, **#13 (H003)**.

## Purpose & placement

The bindings reside **committed** under `src/EBICO.Core/Schema/` (decision
[ADR-0006](../adr/0006-generierte-xsd-bindings-committen.md)). The underlying
**XSDs remain proprietary and untracked** ([ADR-0003](../adr/0003-umgang-mit-proprietaeren-schemas.md));
only the generated `.cs` are in the repo. This lets the CI build and test the
protocol core without needing the schemas.

> The files carry a `// <auto-generated />` header — **do not edit by
> hand**. Changes happen via schema update + regeneration; the few
> unavoidable corrections run as a reproducible script step, see
> [Manual fixups](#manual-fixups-after-generation).

## Tooling & regeneration

- Generator: **[XmlSchemaClassGenerator](https://github.com/mganss/XmlSchemaClassGenerator)**
  (`dotnet-xscgen`, MIT), exactly pinned in `.config/dotnet-tools.json`.
- Driver: `scripts/generate-bindings.sh` (one xscgen run per version with
  namespace mapping; shared schemas are deduplicated, see below).

Regeneration (maintainer step after a schema update):

```bash
# 1) Schemas lokal beziehen (proprietär, nicht im Repo)
./scripts/fetch-schemas.sh --zip ~/Downloads/<ebics_3.0_schema>.zip --version H005
#    ... ebenso H004 / H003

# 2) Tool wiederherstellen (einmalig pro Clone)
dotnet tool restore

# 3) Bindings neu generieren und mit-committen
./scripts/generate-bindings.sh --all
```

## Manual fixups after generation

`generate-bindings.sh` is **not a pure generator**: after each run it applies
`apply_binding_fixups()` — documented, minimal corrections to generated
code that xscgen cannot perform itself. They deliberately reside **in the script** and
not just in the committed `.cs`, otherwise they would have quietly disappeared
after the next schema update. If a fixup does not find its pattern, **the script aborts**
(exit ≠ 0) instead of skipping it.

| Fixup | File(s) | Why | Guard |
|---|---|---|---|
| Remove `abstract` from `OrderDetailsType` | `Schema/{H003,H004,H005}/OrderDetailsType.cs` | xscgen does **not** translate the XSD `<restriction>` that types `OrderDetails` in the static header more concretely. The abstract base type forces the `XmlSerializer` to a `xsi:type` discriminator that real foreign clients do not send → their INI/HIA/HPB are rejected ([ADR-0029](../adr/0029-interop-fixes-reale-clients.md), Issue #117). | `OrderDetailsBindingTests` |

The `[XmlInclude]` attributes and the concrete sub-types remain in place: `xsi:type`
is still **accepted**, only no longer **required**. The sub-types carry no
own members in all three versions, so the intervention costs no
information content.

> **Rule for new fixups:** only if there is a documented interop reason; always
> with a comment in the generated file **and** a guard test; always list here.
> Everything else belongs solved as a schema/generator update.

## Namespaces & layout

Own C# namespaces per version ([ADR-0004](../adr/0004-multi-version-strategie.md)).
The **truly shared** schemas (W3C xmldsig, HEV/H000, signature Sxxx) are
generated **once** under `Schema/Shared/` and referenced by the versions —
this avoids three identical copies of the same XML types.

| Folder | C# namespace | XML namespace | used by |
|---|---|---|---|
| `Schema/H005/` | `EBICO.Core.Schema.H005` | `urn:org:ebics:H005` | H005 |
| `Schema/H004/` | `EBICO.Core.Schema.H004` | `urn:org:ebics:H004` | H004 |
| `Schema/H003/` | `EBICO.Core.Schema.H003` | `http://www.ebics.org/H003` | H003 |
| `Schema/Shared/XmlDsig/` | `EBICO.Core.Schema.XmlDsig` | `http://www.w3.org/2000/09/xmldsig#` | all |
| `Schema/Shared/Hev/` | `EBICO.Core.Schema.Hev` | `http://www.ebics.org/H000` | all |
| `Schema/Shared/Signature/S001/` | `EBICO.Core.Schema.Signature.S001` | `http://www.ebics.org/S001` | H003, H004 |
| `Schema/Shared/Signature/S002/` | `EBICO.Core.Schema.Signature.S002` | `http://www.ebics.org/S002` | H005 |

Important root types per version: `EbicsRequest`, `EbicsResponse`,
`EbicsUnsecuredRequest`, `EbicsNoPubKeyDigestsRequest`, `EbicsUnsignedRequest`,
`EbicsKeyManagementResponse`; HEV pair (`HevRequestDataType`/`HevResponseDataType`,
root elements `ebicsHEVRequest`/`ebicsHEVResponse`) in the shared namespace `Hev`.

## XmlSerializer notes (pitfalls)

- **Optional value types:** with `--nullable`, xscgen generates a `T?` adapter
  property over the `…Value`/`…ValueSpecified` pair (e.g. `EbicsRequest.Revision`
  is `byte?`). This avoids the classic *Specified* data loss. The tests
  check this specifically (value survives round-trip; `null` is omitted).
- **Substitution groups** (`OrderParams`/`EBICSOrderData`, incl. BTF in H005)
  are lowered to an `object` property with several `[XmlElement(typeof(...))]`
  — round-trips correctly (type and element name are preserved).
- **`xs:any ##other`** becomes `Collection<XElement>` (structure-faithful, not
  strongly typed). `mixed content` occurs only in the xmldsig types.
- **Determinism:** `--commandArgs-` turns off the (path-dependent) command-line
  comment, `--separateFiles` keeps diffs small.

## Version differences

| Aspect | H003 | H004 | H005 |
|---|---|---|---|
| Protocol namespace | `http://www.ebics.org/H003` (legacy) | `urn:org:ebics:H004` | `urn:org:ebics:H005` |
| Signature schema | S001 (`ebics_signature.xsd`) | S001 (`ebics_signature.xsd`) | S002 (`ebics_signature_S002.xsd`) |
| File names of the XSDs | without a suffix (`ebics.xsd`, …) | `…_H004.xsd` | `…_H005.xsd` |
| Orders/BTF | smaller | medium | + BTF OrderParams (`BTDOrderParams`/`BTUOrderParams`) |

H003 and H004 are structurally very close; the most striking H003 special case is the
differing (old) protocol namespace. The root-type set and round-trip behaviour
are identical across all three versions.

## Why committed?

In short: so that the CI can build/test the protocol core without proprietary schemas.
Rationale and licence trade-off: [ADR-0006](../adr/0006-generierte-xsd-bindings-committen.md)
and [../legal/ebics-licensing.md](../legal/ebics-licensing.md). The XSDs themselves
remain untracked.

## Tests

- **Tier A** (`tests/EBICO.Tests/Schema/XmlBindingRoundTripTests.cs`): CI-safe
  self-consistency round-trips (serialize → deserialize → serialize, canonically
  stable via `CanonicalXmlComparer`) plus a hand-written HEV wire example
  that checks the binding to the real wire format.
- **Tier B** (`tests/EBICO.Tests/Schema/SampleXmlRoundTripTests.cs`): validates
  against **real** EBICS sample XML, if present locally; skips itself in
  the CI (samples are proprietary, cf. `SampleXml`/ADR-0003).
- **Fixup guard** (`tests/EBICO.Tests/Serialization/OrderDetailsBindingTests.cs`):
  pins the only manual intervention in generated code (`OrderDetailsType`
  not abstract; `xsi:type` is accepted, but not emitted). A
  regeneration without the fixup step is caught here immediately.
